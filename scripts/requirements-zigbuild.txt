# Hash-locked zig cross-toolchain for the musl phase-server builds, installed
# with --require-hashes by the workflows that cross-compile and by the
# Dockerfile's compile stage.
#
# The pins name particular wheels, not merely versions, and PyPI permits wheels
# to be added to an already-published version. A hash mismatch here is therefore
# far more likely to be a new upload than tampering.
#
# pip reports that as HashMismatch, printing the Expected sha256 from this file
# beside the Got hexdigest of what it downloaded. Do not paste the Got digest in:
# it is the hash of whatever actually arrived, which is equally what a tampered
# artifact would present. Verify the digest against PyPI's published file listing
# for that version first, then add it.
#
# Neither package publishes an sdist, so pip can never build from source here --
# which is why this set is complete rather than happy-path, and why
# --require-hashes cannot trip over an unlisted build dependency such as
# setuptools or wheel.
#
# manylinux x86_64 and aarch64 wheels: every workflow runner is x86_64, while the
# Dockerfile's compile stage runs on whatever the build host is. The ziglang wheels
# also carry musllinux_1_1, so one set serves the Ubuntu runners and the
# Debian-based image stage alike.
